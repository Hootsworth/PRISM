## Locked split and leakage control

- **Train:** 98 of the 115 official train instances; two indexed pairs per instance (196 pairs).
- **Validation:** 17 official train instances (34 pairs), stratified by camera using deterministic largest-remainder allocation and seed 20261106.
- **Test:** all 29 official test instances (32 blocks each, 928 paired blocks). Never train, select checkpoints, or tune on test.

Assign all indexed images and patches from an instance to one split before patch extraction. Do not split patches randomly. Validation camera counts are S6=2, GP=4, N6=3, G4=1, IP=7. All cameras occur in training; this is a held-out-instance test, not a held-out-camera test. The test split has capture groups but does not provide per-capture CFA/camera/ISO/AsShotNeutral/ColorMatrix2 metadata. Leave these unknown.

The split was generated by `scripts/audit_siddcc_expanded.py`. Preserve the exact CSV and SHA-256 from the data audit. Do not regenerate the split silently. Any later split change requires a new manifest and run ID.

## Task and targets

Primary full-ISP experiment: `NOISY_RAW_{idx}.MAT` → `GT_SRGB_{idx}.PNG`, using exact instance/index mapping. Input remains black-subtracted normalized float32, unclipped. Target is camera-pipeline-rendered 8-bit sRGB. Secondary ablation: `NOISY_RAW` → `NOISY_SRGB` isolates rendering agreement from denoising; it is not the primary clean reconstruction task. Optional RAW denoiser is a separate B1 experiment with `NOISY_RAW` → `GT_RAW` and its own RAW-domain score table.

Use the metadata-free model proposal on official test blocks. CFA-pattern and camera-conditioned variants require a verified metadata source for test and must not replace unknown values with train averages.

## Metrics and domains

| Metric | Domain and definition | Range and aggregation |
|---|---|---|
| RGB PSNR | Prediction vs `GT_SRGB` after conversion from uint8 to float32 `[0,1]`; same spatial crop and RGB channel order. | Fixed `data_range=1.0`; no per-image rescaling. Compute block scores, aggregate 32 blocks within each test instance, then report across 29 instance groups. |
| RGB SSIM | Same display-encoded sRGB pair, aligned and identically cropped. | `data_range=1.0`; fix window/settings. Aggregate per instance before across instances. |
| Delta E 2000 | Convert predicted and target standard sRGB using a declared sRGB/D65→XYZ→Lab path; compare corresponding pixels. | Report mean/median and fixed percentile per instance. This is target-relative appearance error, not measured colorimetric accuracy; no chart or reference profile is available. |
| LPIPS | Display-referred RGB prediction/reference in sRGB with a named implementation/backbone and fixed normalization. | Aggregate per instance; inappropriate on Bayer mosaics or unrendered linear RAW. |
| RAW RMSE/PSNR | Only noisy-vs-GT RAW input baseline or a separate RAW-denoiser output. | Original normalized Bayer values, fixed nominal `data_range=1.0`, retain negatives/overrange. Not a metric of the RGB-output B1 model. |
| Runtime, memory, params, checkpoint bytes | Full RAW-to-sRGB path and model-only inference separately. | Same device and software; record precision/backend, parameters, serialized size, process RSS and accelerator peak allocation. |

A dataset-matched sRGB score measures agreement with the SIDD-CC rendering and target estimator, not universal color fidelity or camera-independent perceptual quality. Do not make a Delta E color-accuracy claim without calibrated color references.

## B0/B1/B2 comparison

- **B0:** frozen deterministic demosaic + matrix/color conversion + optional display rendering. It does not denoise or sharpen. Do not retune B0 on test.
- **B1:** standalone learned full-frame Bayer-to-sRGB model; a tile refiner alone is not B1.
- **B2:** future B0 base plus sensor-consistency audit and selective learned tile refinement; report its audit and scheduling costs separately.

Use validation captures with their per-capture metadata for a common B0/B1 tuning comparison. For a final official-test comparison, B0 first needs verified test CFA, AsShotNeutral and ColorMatrix2 metadata. These are absent from current test blocks, so a B0 score on that split is currently blocked. Report B1 official-test quality separately if metadata is not obtained; do not combine it with B0 validation results as a same-split comparison.

## Runtime and resource protocol

Run on the same named hardware and software versions; record CPU model/thread settings and any accelerator/backend. For accelerator timing synchronize before and after each timed section. Do one warm-up and at least 10 measured repetitions per scene/block batch; interleave method order to reduce thermal/load bias. Report median, mean and IQR or standard deviation by instance and overall.

1. **End-to-end:** file load and validation, preprocessing, complete full-frame or tiled inference, output stitching and declared sRGB encoding. Exclude download and metric computation.
2. **Model-only:** preloaded packed tensor through the network and tile stitching.

Measure process high-water RSS and documented accelerator peak memory. Record tile size/overlap and seam checks. Benchmark CPU and accelerator separately. No mobile or real-time claim without a named phone measurement.

## Stopping and reporting rules

Use validation only for checkpoint selection, early stopping and hyperparameter choice. Record random seed, optimizer, scheduler, batch/crop size, augmentations, epochs and checkpoint hash. Publish per-camera results as descriptive, since the split does not hold out cameras. Report limitations from test metadata absence and small number of cameras. Do not claim novelty or state-of-the-art without a separate literature review.
